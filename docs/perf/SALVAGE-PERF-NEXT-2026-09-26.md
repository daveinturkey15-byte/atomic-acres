## Three inspectable profiling targets

1. **Post graph and drawing-buffer cost.** VERIFIED: `src/core/post.ts:375` builds four MRT outputs. The far GTAO uses 32 samples (`:422`), the near kernel 16 (`:455`), with separate denoising; SSR is constructed at `:522`; atmosphere includes a half-resolution smoke stage at `:540`; bloom is subsequently composed. These are graph dependencies, not evidence of their measured GPU duration. Installed GTAO and SSR default to `resolutionScale = 1`; renderer DPR is capped at 2 (`src/core/renderer.ts:78`). OPEN: this is a strong GPU profiling candidate, not a diagnosed GPU bottleneck. Uniform menu toggles multiply existing results (`src/core/post.ts:501`); turning a contribution to zero is **not proof its pass stopped executing**. Inspect actual pass timings/dependencies before treating a toggle comparison as an optimization result. Preserve the MRT-first-render and shared output-buffer rules documented atop post.ts.

2. **Character mixer, planting and carry constraints.** VERIFIED: all actual match actors continue animation each frame: distance skipping in `src/characters/system.ts:193` applies only when `rootMotion !== false`, while gameplay body presentation disables root motion. `src/characters/blend.ts:612` advances the mixer, `:619` solves plants and `:707` applies carry constraints; matrix updates appear inside the constraint path (`:209`, `:226`, `:244`, `:723`, `:770`, `:789`). OPEN: trace per-character and aggregate time before changing these calls. A bounded canary may reuse already-valid transforms or avoid demonstrably repeated traversal **only after proving the dependency order**. Do not re-enable coarse 20/10 Hz gameplay animation: the source explicitly preserves smooth skeletons on interpolated moving roots. Keep foot contact, grip, prone, reload, grenade throw and death/revive acceptance cameras unchanged.

3. **World shadow pass.** VERIFIED: renderer shadows are enabled (`src/core/renderer.ts:76`) and the directional sun uses a 4096² shadow map (`src/core/world.ts:190`). OPEN: measure shadow pass CPU submission/GPU time and changing casters before proposing static/dynamic separation. A canary must retain moving actor/weapon shadows, atmosphere/time-of-day invalidation, and existing fitted shadow bounds. Simply freezing all shadow updates or reducing the map is not an accepted repair; compare identical roofline, interior, actor and contact-shadow views before any promotion.

VERIFIED: no proven dead frame-loop subsystem was found. `GameClient.view()` allocates a small object (`src/game/client.ts:460`) and main reads it before and after simulation (`src/main.ts:582`, `:613`); those two reads can represent different state, so collapsing them without an event-order proof would change behavior. This is a lower-priority allocation measurement, not a demonstrated explanation of the frame-rate gap. Reflective-surface `refresh()` is version-guarded (`src/core/reflective-surfaces.ts:334`); its startup bake and authoring/debug vector allocations must not be misreported as unconditional per-frame work.
