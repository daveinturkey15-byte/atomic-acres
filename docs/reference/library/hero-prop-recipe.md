# Hero-prop recipe — concept image to game-ready GLB, locally, on this machine

**Route:** `comfyui-native-3d` / Trellis.2, entirely on `dave-gaming-pc`. No paid API, no
custom ComfyUI node pack, nothing installed.
**Status:** the capability works end to end and is reproducible. Whether any generated
mesh should enter the repository is a **per-asset owner decision** — Atomic Acres is
procedural-art-first and its contract forbids imported meshes for arena art. See the
evaluation record `hero-prop-canary-2026-09-19.md` for the first canary and its verdict.
**Executable procedure:** skill `comfyui-3d-native-pipeline`. This file is the
this-repo, this-machine specialisation of it, written from a run that actually happened.

---

## 0. The two scripts

| | |
|---|---|
| `scripts/art-gen/comfy_trellis.py` | the pipeline client: preflight, concept image, Trellis.2 graph, receipts |
| `scripts/art-gen/prop-orbit.mjs` | the acceptance renderer: three r180 WebGPU page with this project's light rig, fixed cameras, 12-frame orbit, underside, map-strip falsifier |

Neither writes into `public/`, `src/`, `dist/` or the git index. Generated bytes live
outside the repo until the owner decides otherwise.

```
python scripts/art-gen/comfy_trellis.py preflight
python scripts/art-gen/comfy_trellis.py concept --prompt "..." --out <scratch>/concept.png
python scripts/art-gen/comfy_trellis.py mesh --image <scratch>/concept.png \
       --name mything --out-dir <scratch>/out --game-faces 3000 --atlas 2048 --ao-distance 0.03
node scripts/art-gen/prop-orbit.mjs --mode glb --glb <scratch>/out/mything-game_00001_.glb \
       --out <scratch>/frames --tag mything --size 100,<height-in-metres>,100
node scripts/art-gen/prop-orbit.mjs --mode procedural --out <scratch>/frames --tag procbox
```

## 2. The graph

Built as API-format JSON in `trellis_workflow()`. It is the Trellis.2 branch of the
shipped template `comfyui_workflow_templates_json/templates/3d_pixal3d_trellis2_image_to_model.json`
with the frontend-only nodes resolved away: `ComfySwitchNode` (the Pixal3D/Trellis
boolean, and the background-removal bypass) and the `PreviewImage`/`MaskPreview`
pass-throughs are wired straight through.

```
LoadImage ─┬─────────────────────────────► ImageCropToMask(1024,1024,pad 1.1) ──► Trellis2Conditioning
           └► RemoveBackground(birefnet) ──┘                    (clip_vision dino_v3_vit_l)

UNETLoader(trellis_2_int8_convrot)
   ├─ CFGOverride(cfg 1, start 0.667) ─ RescaleCFG(0.7) ─ ModelSamplingSD3(5) ─► KSampler STRUCTURE
   ├─ CFGOverride(cfg 1, start 0.769) ─ RescaleCFG(0.5) ─────────────────────► KSampler SHAPE, UPSAMPLE
   └─ (raw) ──────────────────────────────────────────────────────────────────► KSampler TEXTURE

EmptyTrellis2LatentStructure ─► KSampler(seed 56, 12 steps, cfg 7.5, euler/normal)
  ─► VaeDecodeStructureTrellis2(shape vae, res "32") ─► Trellis2ShapeStage
  ─► KSampler(seed 42, 20 steps, cfg 7.5, euler/normal)
  ─► Trellis2UpsampleStage(target 1536) ─► KSampler(seed 42, 12 steps, cfg 7.5, euler/simple)
  ─► VaeDecodeShapeTrellis ──► mesh + shape_subdivides
  └─ Trellis2TextureStage ─► KSampler(seed 43, 12 steps, cfg 1.0) ─► VaeDecodeTextureTrellis(texture vae)

mesh ─► GetMeshInfo ─► RemeshMesh(768, udf, band 1, smooth_iters 20)
  ├─ DecimateMesh(700000, midpoint) ─ GetMeshInfo ─ MeshSmoothNormals(180) ─ PaintMesh ─ MeshToFile3D ─ SaveGLB   [sculpt]
  └─ DecimateMesh(  3000, midpoint) ─ GetMeshInfo ─ MeshSmoothNormals(180) ─ UnwrapMesh(pec, 2048)
        ├─ BakeTextureFromVoxel(2048, reference_mesh = the raw decoded mesh) → base/metal/rough
        ├─ BakeNormalMapFromMesh(low = unwrapped, high = RemeshMesh, 2048, cage 0.05)
        └─ BakeAmbientOcclusion(low = unwrapped, high = RemeshMesh, 1024, 64 spp, max_distance 0.03)
      ─► ApplyTextureToMesh ─ MeshSmoothNormals(180) ─ MeshToFile3D ─ SaveGLB                                    [game]
```

Two `DecimateMesh` branches in **one** submit is deliberate: "triangles before and after
decimation" then comes from two real files, not from a node's target number, and one
generation gives one wall time and one VRAM peak.

### Three things about the API format that cost time

- **Dynamic combos are flat keys.** `RemeshMesh.sign_mode` is a `COMFY_DYNAMICCOMBO_V3`.
  In an API prompt you send `"sign_mode": "udf"` **plus** `"sign_mode.qef": false`,
  `"sign_mode.drop_inverted_components": false`, … and the server reassembles them into
  the nested dict `execute()` expects (`comfy_api/latest/_io.py:build_nested_inputs`).
  Same shape for `DecimateMesh.placement_mode`.
- **`GetMeshInfo` is not an output node**, so its STRING never reaches `/history`. Route
  it into `PreviewAny` and read `outputs.<node>.text`.
- **`SaveGLB` reports under `ui["3d"]`**, not `images`. Fetch with
  `/view?filename=…&subfolder=…&type=output`. Prefer it over `Save3DAdvanced`, whose
  `viewport_state` input is a frontend widget.

### Deviations from the shipped template, and why

| | template | here | why |
|---|---|---|---|
| atlas / bake size | 4096 (driven by a `PrimitiveInt`) | **2048** | a 0.6 m crate; 4096 is three 64 MiB textures for set dressing |
| `DecimateMesh` | 700 000 | **700 000 + 3 000** | 700 k is a *sculpt* budget. The game budget is the one that ships |
| `BakeAmbientOcclusion.max_distance` | 0.71 | **0.03** | see below — this one is a defect, not a taste call |

## 3. The AO gotcha (found by looking at the atlas, 2026-09-19)

**Symptom.** The exported crate renders as dark olive with hard black wedges across it,
and reads metallic. It looks broken, not merely "a bit flat".
**Cause.** `BakeAmbientOcclusion.max_distance` ships as **0.71** in the official template.
Trellis emits the mesh at roughly unit scale (this crate: 0.63 × 0.99 × 0.47), so an AO
ray travels 71 % of the object and reaches the far wall from almost everywhere. The bake
goes near-binary: measured **56.9 % of texels below 16/255** and 22.5 % above 240, mean
85.4. The template's value is presumably right for the axe it was authored against.
**Correction.** Set `max_distance` to a few percent of the object's own extent.
`--ao-distance 0.03` on this crate: mean **182.0**, only 2.0 % below 16 — a real ambient
field instead of a mask. Same numbers, same seeds, 20 s (everything upstream cache-hits).
**Verify.** Open the AO PNG and measure it; do not judge it from the shaded preview.
A histogram with two spikes at the ends is the failure signature.

The same reasoning applies to `BakeNormalMapFromMesh.cage_distance` (0.05 = 5 % of a unit
object). It was left alone here — one bounded change at a time — and is the next thing to
check if a candidate shows smeared relief.

## 4. Acceptance is in the target runtime, never in `Preview3DAdvanced`

`prop-orbit.mjs` serves a single-page three r180 `WebGPURenderer` scene over an ephemeral
port and drives real Chrome over CDP (playwright's bundled chromium has no WebGPU
adapter), headless, on the second monitor, through `scripts/lib/proc-guard.mjs`. The
numbers are **copied** from the game — nothing under `src/` is imported, so no lane's file
is touched:

| | value | source |
|---|---|---|
| tone mapping / exposure | `ACESFilmicToneMapping`, 1.09 | `src/core/renderer.ts` |
| output colour space | `SRGBColorSpace` | `src/core/renderer.ts` |
| sun | dir `(0.45, 0.55, −0.7)` normalised, intensity 3.35, tint `PAL.sunColor` `offsetHSL(−0.008, 0.05, −0.004)` | `src/core/world.ts` |
| hemisphere | `PAL.skyTop` / `PAL.bounce`, 0.95 | `src/core/world.ts` |
| opposing fill | `PAL.skyTop` `offsetHSL(0.02, 0.04, −0.02)`, 0.25 | `src/core/world.ts` |
| environment | the same 512×256 equirect sky bake, `environmentIntensity` 0.9 | `src/core/world.ts` |
| fog | `FogExp2(PAL.fog, 0.0016)` | `src/core/world.ts` |
| camera | 72° fov | `src/core/world.ts` |

It captures front / side / three-quarter / low / back / **underside** / 3 m / 15 m plus a
12-frame orbit, and reports from inside the runtime: triangles, materials, texture sizes
and **colour spaces**, the world bounding box after fitting, and where the pivot sits
inside it.

`--mode procedural` renders the `yards.ts` `crateStack` as flat-colour boxes. That is the
**floor** of the incumbent, not the incumbent: the real thing uses `mat.timber` /
`mat.timberDark`, which carry generated `map` + `roughnessMap` + `normalMap`. For an
honest comparison photograph the shipped crate in the running game instead — the shared
preview on :4188, playcap's Chrome launch block, `__NT.teleport` (never `goto()`, which
sets `cameraHeldByQA`). The orange front-lawn stack is at world **x 0, z −9.1**
(`hx(0.0)`, `fz(ORANGE, 0.25)` = −(7.0 + 0.25 × 8.4)); yaw convention is
`forward = (−sin y, 0, −cos y)`, so stand at `(0, −6.1)` with yaw 0.

**`--strip aoMap,normalMap,…` is the attribution falsifier.** A defect that survives the
removal of a map is not that map's fault. Note that stripping `metalnessMap` leaves
`metalness = 1` from the glTF `metallicFactor`, so that frame goes shiny — an artefact of
the test, not of the asset.

## 5. What comes out, and what to check

Measured on the canary (full numbers in the evaluation record):

- **Colour space.** Verified in the runtime, not the viewer: `map.colorSpace === "srgb"`,
  and `normalMap` / `roughnessMap` / `metalnessMap` / `aoMap` all `""` (NoColorSpace).
  Correct.
- **Material.** One `MeshStandardMaterial`, `metalness = 1`, `roughness = 1`,
  `side = DoubleSide`. The factors are 1 because glTF multiplies them by the ORM texture,
  whose blue channel measures **0.2/255** — so it is a dielectric in practice. Any path
  that drops the `metalnessMap` renders it fully metal.
- **Textures.** Three 2048² PNGs: base colour, packed ORM (AO in R, roughness in G,
  metallic in B — `occlusionTexture` and `metallicRoughnessTexture` share one image), and
  the normal map. ≈ **64 MiB of VRAM** uncompressed with mips, and a 9.6 MB GLB.
- **Pivot.** Dead centre of the bounding box (measured 0.499 / 0.497 / 0.504 normalised),
  **not** the contact point. Re-seat it before anything stands on the ground.
- **Scale.** The generator has no idea how big the thing is. Fit deliberately, on one
  axis, and say which: `--size 100,1.18,100` fits height and lets the footprint fall out.
- **UV atlas.** Look at it. 2 906 faces became **214 charts** with a lot of dead space and
  many slivers; effective texel density is well under what 2048² suggests.
- **The back and the underside.** One reference image cannot establish hidden geometry.
  The underside frame exists to be looked at, and on this canary it is the worst frame.

## 6. Before anything is committed

Atomic Acres does not have an asset until `assets.manifest.json` carries it and
`npm run qa:asset-provenance` / `npm run verify:provenance` pass. Record, in the same step
as the export: route, generator, every weight filename **with its SHA-256 as resolved by
the running server**, ComfyUI version, the node set observed, the concept prompt and seed,
every KSampler seed and step count, the licence position with the date each file was read,
and the SHA-256 of the exported GLB. `comfy_trellis.py` writes all of this to a receipt
JSON beside the output.
