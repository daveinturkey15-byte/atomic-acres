# Standalone Nuketown 2025 — Production Catalog Pipeline

This document defines the lifecycle, schema constraints, concurrency rules, and gate verification requirements for the standalone **Black Ops 2 Nuketown 2025** recreation.

The catalog manages the full inventory of weapons, killstreaks, operators, animation frames, and fidelity scenario camera views, guiding each asset from initial image concept to verified production runtime.

## 2. The 8-Stage Production Lifecycle

Every asset in the catalog transitions through eight explicit, verifiable stages:

```
[1. Image Concepts]
        │
        ▼
[2. Isolated Multiview Asset References]
        │
        ▼
[3. Blender / Trellis Authoring]
        │
        ▼
[4. Topology, PBR, UV, Scale, Rig & Collision]
        │
        ▼
[5. Authoritative Mechanics and UI]
        │
        ▼
[6. Actual Multiplayer / Browser Screenshots]
        │
        ▼
[7. Immutable Candidate]
        │
        ▼
[8. Root Acceptance]
```

### Stage 1: Image Concepts
- **Goal:** Establish visual target fidelity against original Black Ops 2 theatre frames or concept boards.
- **Requirements:** High-resolution gameplay captures or prompt concepts under target lighting conditions.
- **Manifest State:** `queued`. No fake files or speculative hashes may be declared.

### Stage 2: Isolated Multiview Asset References
- **Goal:** Produce clean, isolated orthographic or canonical views (front, side, rear, top) with transparent backgrounds.
- **Requirements:** Images must be written to disk, non-zero length, verified against real image magic headers (PNG/JPEG/WEBP), and recorded with exact SHA-256 digests.
- **Manifest State:** `reference-generated`.

### Stage 3: Blender / Trellis Authoring
- **Goal:** Synthesize initial 3D geometry from isolated references using Trellis 2 or Blender blockouts.
- **Requirements:** Geometry must be saved as editable source files or intermediate glTF meshes. Cloud generation workflows operate independently and asynchronously.

### Stage 4: Topology, PBR, UV, Scale, Rig & Collision
- **Goal:** Prepare game-ready assets adhering strictly to standalone Nuketown budgets:
  - **Triangles:** Weapon models under ~2,500 tris; killstreak drones under ~1,500 tris; total scene draw calls under 1,200 and triangles under 900,000 across all stations.
  - **Materials:** Use singleton materials from `src/core/materials.ts`. Never construct individual materials per builder or per frame.
  - **Scale:** Derived deterministically from `src/core/layout.ts`.
  - **Rigging:** Humanoid operator skeleton or first-person viewmodel arm hierarchy.
  - **Colliders:** Honest bounding boxes or simplified convex hulls.
- **Manifest State:** `authored`.

### Stage 5: Authoritative Mechanics and UI
- **Goal:** Implement authoritative game logic and interface bindings:
  - Weapon firing rates, recoil curves, reload timings, and iron-sight ADS camera offsets.
  - Streak deployment backoff hold timers (verified by `scripts/_verify-streak-reject.mjs`), minimap icons, and audio hooks.
  - Code entrypoints must reside in `src/` as valid TypeScript/JavaScript modules. Generated images can **never** count as runtime code or assets.
- **Manifest State:** `integrated`.

### Stage 6: Actual Multiplayer / Browser Screenshots
- **Goal:** Photograph the asset rendered inside the live frame loop of the real game.
- **Execution:** Headless Chrome spawned via CDP (`scripts/lib/proc-guard.mjs`) against `vite preview` on port `:4188`.
- **Constraint:** Must look at actual frames captured through `npm run playcap` and `scripts/capture.mjs`. Canvas-only synthetic mocks are rejected.

### Stage 7: Immutable Candidate
- **Goal:** Assemble an immutable verification record before proposing root integration.
- **Requirements:**
  - `verification.receipt`: Path to a JSON receipt generated by the test runner.
  - Matching `assetId`, matching `buildHash`, outcome strictly equal to `"pass"`, and explicit `sourcePath`.
  - `visualApproved: true` and `runtimePassed: true`.
  - All declared dependencies must already be in `verified` stage.
- **Manifest State:** `verified`.

### Stage 8: Root Acceptance
- **Goal:** Promotion into root repository `C:/Users/david/Desktop/stuff/nuketown`.
- **Verification:** Root test suite passes (`npm run check`, `npm run verify`), with checkpoint updated in `docs/handoff/CURRENT.json`.

## 3. Concurrency and Execution Discipline

1. **Serial Local GPU and Browser Verification:**  
   Local Chrome CDP harnesses and Vite preview instances (`:4188`, `:4191`) touch hardware GPU adapters (D3D11/ANGLE/WebGPU) and shared ports. They **must run serially**. Never launch concurrent browser harnesses that risk port collisions or corrupted frame timing.
2. **Independent Cloud / Offline Authoring:**  
   Trellis 2, image generators, and external authoring pipelines execute out-of-process without holding local dev server or worktree locks.
3. **CPU-Bound Gate Validation:**  
   The catalog gate (`catalog-gate.mjs`) requires no network, no browser, and no GPU. It can be run continuously in any CI or pre-commit step.

## 4. Manifest Schema and Validation Contract

Every item in the catalog manifest complies with the following contract:

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique identifier (e.g., `weapon-m8a1`, `streak-uav`) |
| `kind` | `string` | One of `weapon`, `killstreak`, `grenade`, `operator`, `animation`, `scenario` |
| `displayName` | `string` | Human-readable title |
| `referenceSource`| `string` | Original BO2 theatre frame, URL, or design document source |
| `dependencies` | `string[]` | IDs of prerequisite assets (strictly acyclic DAG) |
| `images` | `object[]` | Array of `{ path, sha256, role }` |
| `stage` | `string` | `queued`, `reference-generated`, `authored`, `integrated`, `verified`, `rejected` |
| `model` | `object \| null`| `{ path, sha256, triangles, materials, decodedTextureBytes }` |
| `runtime` | `object \| null`| `{ entrypoint, assetPath, sourceCommit }` |
| `verification` | `object \| null`| `{ receipt, buildHash, visualApproved, runtimePassed }` |
| `owner` | `string` | Engineer or subagent responsible (e.g., `Astra`) |
| `nextAction` | `string` | Specific, actionable next engineering task |

### Validation Enforcements
- **Containment Security:** All paths (`images[].path`, `model.path`, `runtime.entrypoint`, `runtime.assetPath`, `verification.receipt`) must be relative, normalized, and strictly contained inside root. Traversal segments (`..`), absolute drive paths (`C:\...`), POSIX root paths (`/...`), and symlink targets outside root are rejected.
- **Image Integrity:** Image files must exist, be greater than 0 bytes, match valid image magic headers (PNG: `89 50 4E 47 0D 0A 1A 0A`, JPEG: `FF D8 FF`, WEBP: `RIFF...WEBP`, GIF: `GIF87a`/`GIF89a`), and match declared SHA-256 digests.
- **Generated-Image Disallowance:** A row cannot claim `integrated` or `verified` without runtime code (`.ts`, `.js`, `.mjs`, `.cjs`). An image file cannot be specified as `runtime.entrypoint` or `runtime.assetPath`.
- **Receipt Proof:** Verification requires an actual receipt JSON file containing matching `assetId`, matching `buildHash`, `outcome: "pass"`, and matching `sourcePath`. Truthy field flags alone do not constitute proof.
- **Dependency Hierarchy:** A row cannot transition to `verified` unless all IDs in its `dependencies` array are already verified.
- **Runtime Gate (`--require-runtime`):** When `--require-runtime` is passed, any manifest with unverified non-rejected items immediately exits with non-zero failure.

## 5. Explicit Record of Unsupported and Unverified Steps

To preserve engineering honesty, the catalog gate explicitly distinguishes between structural contract verification and downstream subjective assessment:

| Dimension | Verified by Catalog Gate (CPU) | Unsupported by Gate (Requires Downstream Verification) |
|---|---|---|
| **File Integrity** | File existence, non-zero size, SHA-256 match, image magic bytes | Texture mipmap quality, texture compression artifacting |
| **Path Safety** | Containment within root, no symlink escapes, no `..` traversal | Directory symlink permissions on external deployment targets |
| **Geometry** | Declared triangle and material counts, model file existence & SHA | Aesthetic silhouette accuracy, UV distortion, mesh seam alignment |
| **Runtime Code** | Entrypoint file existence, non-empty, code extension valid | Authoritative frame loop performance, weapon recoil feel, game balance |
| **Receipt Proof** | Matching buildHash, assetId, outcome pass, valid sourcePath | Human aesthetic signoff (represented by `visualApproved` bit in receipt) |
| **Visual Art** | **NOT VERIFIED** | **Visual taste, photorealism, and BO2 atmosphere cannot be proved by automated gates.** |

> [!NOTE]
> Automated validation confirms contract completeness, structural invariants, hashes, and runtime receipts.
> Validators do NOT prove art quality, aesthetic fidelity, or game feel. Visual signoff requires inspection of actual frames.

The root production catalog currently records 20 weapon sheets, 11 killstreak sheets, 4 grenade sheets, 2 operator rows covering 3 operator images, and one queued operator-pose row. All image-backed rows are `reference-generated` with `model: null` and `runtime: null`; the queued pose row is incomplete by design. The full first-person/world/drop-LOD, reload/ADS/recoil/inspect, hand-contact, 360-degree yaw/bot-forward, map-use, non-gory hit-react, UI/damage/FX, and network proof backlog is recorded in `docs/catalog/production-catalog.json` and its report.

## 6. CLI Usage Guide

### Standard Catalog Validation & Completeness Report
Validates schema, path containment, hashes, and outputs human-readable progress:
```bash
node scripts/catalog/catalog-gate.mjs --manifest docs/catalog/example-manifest.json
```

### Writing Report to Markdown
```bash
node scripts/catalog/catalog-gate.mjs --manifest docs/catalog/example-manifest.json --report docs/catalog/STATUS.md
```

### Production Runtime Gate
Enforces that 100% of required rows are integrated and verified:
```bash
node scripts/catalog/catalog-gate.mjs --manifest docs/catalog/example-manifest.json --require-runtime
```
*(Fails with exit code 1 if any backlog or unverified items remain).*

### Structured JSON Output
```bash
node scripts/catalog/catalog-gate.mjs --manifest docs/catalog/example-manifest.json --json
```

### Running the Test Suite
Runs all 55 synthetic unit, security, and mutation assertions:
```bash
node scripts/catalog/verify-catalog-gate.mjs
```
