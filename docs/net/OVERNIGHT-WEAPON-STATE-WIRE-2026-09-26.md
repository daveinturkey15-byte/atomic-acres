# Weapon authority wire — bounded overnight pass

VERIFIED — The source uses `game/host-weapon-state.ts` as the single intent/state contract. The wire adds reliable `weapon-intent` and private `weapon-state` messages. The existing RTC transport sends everything except movement input/world pose through its reliable ordered control channel; neither channel policy nor gameplay cadence changes here.

VERIFIED — `MatchDriver.weaponIntent({weaponId, action})` returns an assigned sequence or null. Drivers supply life/sequence and construct only the canonical equip, reload, charge-start and cancel fields. The receive validator rejects client-authored actor, clock, magazine or completion fields; GameHost retains life, replay, ownership, active-weapon and gameplay admission. A connected room seat supplies actor identity. Returning an assigned sequence is not acceptance: the controller must await the corresponding authoritative state.

VERIFIED — Solo projects its own state every host tick and immediately after local intent/shot submission. Host rooms send each seat only its own state at 10 Hz, plus intent/shot/spawn/death edges and authenticated resume. The previously broadcast `ordnance-inventory` event is now private too. Public actor samples carry only the actual active weapon identifier; the solo character path uses the same identifier. No opponent magazine state is added to public pose messages. Existing world-drop and pickup events keep their existing semantics.

VERIFIED — `ClientSnapshot.weaponState`, `GameClient.weaponState` and the local `SessionSnapshot.weaponState` provide one self-only projection. Spawn/death clears presentation. State is fenced to the current life and spawn timestamp; lower revisions are refused and equal revisions require nondecreasing localized timestamps. A newer revision can supersede a previous localized timestamp after a clock-offset update: revision is the ordering authority. Absolute `at` crosses the existing host-to-guest clock boundary once; reload and charge spans do not change.

VERIFIED — Exact `resolvedShotSeqs` acknowledgements remain exact and bounded to 64. They are not interpreted as “all lower shots resolved.” A resumed document starts its wire shot domain above **both** the retained admitted ShotWindow sequence and `WeaponState.lastShotSeq`, which also includes refused current-life claims. Receive processing removes older-domain acknowledgements and subtracts the new base; intent sequences remain in the driver-assigned domain. The actual fixture proves admitted 9 / stale-refused 10, then fresh controller 0 → wire 11 → exact controller ack 0. Replaying that fresh shot cannot spend ammunition again.

VERIFIED — Existing room liveness, rather than a new watchdog, triggers trusted charge-only cancellation once when a seat becomes disconnected. The authenticated resume-facts callback performs the same cancellation before constructing welcome state, covering document replacement before the liveness timeout. This invalidates previous charge tickets without consuming a client sequence, changing magazines or discarding an in-progress reload. Normal controller cancellation and trusted connection cancellation remain distinct host operations.

## Explicit compatibility boundary

VERIFIED — No prior match-version/capability handshake existed. The integrator approved requiring `weaponStateProtocol: 1` in hello and welcome for this feature change. A new host checks it before changing any seat, resume binding or kit. A new guest accepts a welcome only from its expected host peer and refuses missing/unsupported capability while connecting. The ordinary lobby message is “GAME VERSIONS DIFFER — REFRESH BOTH GAMES.” A later compatible welcome cannot resurrect a rejected join.

VERIFIED — Capability values remain opaque at the legacy structural hello/welcome parser solely so admission can explain an incompatible or missing value. They are compared strictly to the current integer, never used in arithmetic or treated as authority. Missing, zero, future, string and object values are covered by negative fixtures. This is an intentional compatibility break, not a legacy authority fallback. The root integrator owns preserved, mechanical capability additions to older direct-handshake positive fixtures; their gameplay assertions must remain intact.
